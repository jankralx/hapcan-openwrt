# Using the interface

## Network access

The single Ethernet port is the `lan` bridge (`br-lan`). It has two
addresses at the same time:

| Interface | Address | Purpose |
|---|---|---|
| `lan_dhcp` | from your DHCP server | normal use on a home network |
| `lan` | `192.168.168.100/24`, static | fallback, e.g. a direct cable from a PC without DHCP |

The interface announces itself over mDNS (`umdns`):

- hostname `hapcan-xxxx.local`, where `xxxx` are the last four hex digits of
  the Ethernet MAC address,
- service `_hapcan._tcp` with the hmsg TCP port and the TXT record
  `protocol=hapcan-ethernet`.

Find interfaces on the network from Linux with
`avahi-browse -rt _hapcan._tcp`, or on macOS with `dns-sd -B _hapcan._tcp`.
The PC firewall must accept mDNS (UDP 5353) on that network. For example,
the firewalld zone `nm-shared` used by NetworkManager connection sharing does
not by default: `firewall-cmd --zone=nm-shared --add-service=mdns`.

### More than one interface on a network

- DHCP addresses, the mDNS hostnames and the mDNS service records are all
  unique, so several interfaces work side by side.
- The static fallback address is the same on every interface. Two interfaces
  on one network would both claim `192.168.168.100`, and that address becomes
  unreliable for both. The fallback is meant for a single interface on a
  direct cable. Change it (`uci set network.lan.ipaddr=...`) on interfaces
  that share a network.

### Direct cable from a PC

Give the PC a static address in `192.168.168.0/24`, e.g. `192.168.168.1`,
then `ssh root@192.168.168.100`.

### First login

There is no root password after flashing. SSH in and set one with `passwd`.
After that, SSH asks for the password, or use keys in
`/etc/dropbear/authorized_keys`.

## hmsg (HAPCAN gateway)

Configuration: `/etc/hmsg/config.json`, documented in the
[hmsg README](https://github.com/jankralx/HMSG-openwrt#readme). hmsg reloads the
file when it changes. Restart it (`/etc/init.d/hmsg restart`) after changing
the TCP server settings so the mDNS announcement follows.

The default configuration:

- TCP server on port 1001 (HAPCAN Ethernet interface protocol), as expected
  by HAPCAN Programmer,
- computer ID 254/254 (sender address of frames generated by hmsg),
- time frames from the RTC enabled,
- MQTT and the MQTT gateway disabled. Set `enableMQTT`, `mqttBroker` and the
  topics to use them.

Logs: `logread -e hmsg`.

## CAN bus

The STM32 on the board runs [CANable](https://github.com/normaldotcom/canable-fw) slcan firmware and
appears as `/dev/ttyACM0`. The `slcand` service turns it into the network
interface `can0` at 125 kbit/s (HAPCAN bus speed). A hotplug script brings
`can0` up and restarts hmsg whenever the CANable appears.

Useful commands:

```sh
candump can0                     # watch bus traffic
# HAPCAN frames are 29-bit IDs: frame type (12 bit), response flag, node, group.
# Hardware type request (0x103) to all groups from node/group 254/254:
cansend can0 '0206FEFE#FFFF0000FFFFFFFF'
/etc/init.d/slcand restart       # reconnect the CANable
```

The STM32 firmware is in the `hardware` repository and is flashed over SWD
with an ST-Link: `make flash-stm32` on the build machine.

## Real-time clock

A TI BQ32000 RTC (I2C 0x68, `/dev/rtc0`) keeps time without network. At boot
the system clock is set from it. When NTP synchronises, the time is written
back to the RTC (once per boot and after every NTP time step).

After the backup battery has been empty, the BQ32000 sets its oscillator stop
flag and refuses to report time (`dmesg | grep -i rtc`). The next NTP
synchronisation writes the RTC and clears the flag automatically. Without
network access, set the date and write it manually:

```sh
date -s '2026-01-31 12:00:00'
hwclock -w -u
```

## Voltage measurement (ADC)

A Microchip MCP3422 ADC (I2C 0x6e) measures the bus supply and the RTC battery:

```sh
cd /sys/bus/iio/devices/iio:device0
echo "VBUS $(awk "BEGIN{print $(cat in_voltage0_raw) * $(cat in_voltage0_scale) * 16}") V"
echo "VBAT $(awk "BEGIN{print $(cat in_voltage1_raw) * $(cat in_voltage1_scale) * 2.022}") V"
```

The factors are the resistor dividers on the board. The battery divider is
switched by GPIO 11 to avoid draining the battery: enable it with
`gpioset -c 0 11=1` before measuring and disable it with `gpioset -c 0 11=0`.

## Updating the firmware

Copy a `*-sysupgrade.bin` to `/tmp` and run `sysupgrade -v /tmp/<file>`.
Settings are kept, add `-n` to reset them. From a build machine:
`make deploy HOST=<address>`.

Packages: `apk` (OpenWrt 25.12 and newer). Kernel module packages from the
official OpenWrt repositories do not match this custom kernel. Build them with
the image instead (`config/hapcan.diffconfig`).

## Recovery

- **Failsafe mode**: press `f` + Enter on the serial console when it says
  so during boot (or the reset button on GPIO 38, if fitted). The interface then boots with
  default settings at `192.168.168.100` and no services. `firstboot && reboot` resets
  all settings.
- **Serial console**: UART0 of the HLK-7628N, 57600 baud 8N1.
- **Broken image**: the HLK-7628N U-Boot offers loading an image over TFTP
  from its serial console menu.
